One project, built all the way through

My senior project is a complete product: database, API, security, interface, reports, and testing. Here is how it works and how it is put together.

Senior projectLebanese University, Faculty of Technology2025 – 2026Supervisor: Dr. Youssef Zaki

Personal Finance Manager

A web app where a person tracks expenses, income, monthly budgets, and savings goals in one place, instead of juggling spreadsheets. Every change shows up on the dashboard straight away, and budget alerts appear before spending gets out of hand.

Dashboard: balance, income, expenses and savings at a glance, with live charts and budget progress. Screenshots use sample data.

React 18 + TypeScriptSingle-page app with Tailwind CSS, Recharts, React Router and Axios
REST
JWT
Node.js + ExpressResource-based API: auth, categories, expenses, income, budgets, savings
mysql2
MySQLSix normalized tables linked by foreign keys

What it does

  • New accounts get 14 default categories (10 expense, 4 income) with their own icons and colors.
  • Monthly budgets per category with progress bars that turn yellow near 90% and red past 100%.
  • Notifications for categories over 90% of budget and for expenses above $100.
  • Six CSV report types, with a preview in the app before downloading.
  • Savings goals, a calendar of transactions, and an analytics page with savings rate and budget usage.

How it is secured

  • Passwords hashed with bcrypt (10 salt rounds).
  • JWT tokens that expire after 7 days; middleware rejects invalid tokens with a 401.
  • Parameterized queries against SQL injection.
  • Every data query is scoped to the signed-in user's ID.
  • CORS limited to allowed origins, with validation on both client and server.

How it was built and tested

  • Iterative approach: schema and authentication first, then the API, then the React front end.
  • The dashboard loads its data through four parallel API calls with Promise.all.
  • Endpoints tested with Postman, then a full user journey tested end to end: register, add expenses and income, set budgets and goals, read alerts, export reports.

Taking AI from demo to dependable

SE Factory's Applied AI Engineering Workshop ran for 4 weeks and 12 sessions and ended with one working AI agent. It covered the parts of an AI system that decide whether it can be trusted in production.

LLM APIs

Integrating model APIs with structured outputs, so responses arrive in a predictable shape the rest of the code can use.

Retrieval (RAG)

Embeddings and semantic search over Qdrant and ChromaDB vector stores, with hybrid search and re-ranking, grounding answers in specific documents and data.

Tool and function calls

Designing calls the agent can make reliably, with clear inputs and outputs, and orchestrating agent workflows with LangChain and LangGraph.

Evals and guardrails

Evaluations with RAGAS and DeepEval, plus guardrails and approval gates that test behavior and keep a person in control of risky actions.

Monitoring

Tracing with LangSmith and tracking latency, token usage, errors, and cost, so a system can be run and improved after launch.

This builds on my work at Tawasoul, where I shipped features for an AI-powered interview platform. I can build the web application around a model and the AI layer inside it.
